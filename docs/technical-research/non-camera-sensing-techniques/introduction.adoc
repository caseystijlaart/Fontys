= Introduction

This chapter addresses the first technical research question defined in the project plan (see xref:../../project-plan/project-assignment/research-questions.adoc[Research Questions]):
"Which combination of non-camera sensors provides sufficient 3D spatial resolution to distinguish adult and child height categories within a room-scale interactive space?"

Per the project assignment (see xref:../../project-plan/project-assignment/assignment.adoc[Assignment]), the target system estimates a single person's real-time 3D position and height within the Holobox interaction space without cameras, and exposes that estimate to the Holobox's Unreal Engine pipeline so the Virtual Human can adapt its behaviour accordingly.
This chapter's scope is the question that decision depends on; which non-camera sensing technologies exist, what they have actually been shown to do in the literature, and which module aligns the most with the project's requirements and possible future extensibility.

In scope for this chapter various aspects will be taken into consideration and discussed.
Such aspects involve a literature-backed study of candidate non-camera sensing technologies, the criteria a viable approach has to satisfy, a comparison of specific sensors and sensor combinations against those criteria using current hardware/cost data, and a recommended sensor choice with a staged plan for de-risking it, detailed in the sections that follow.

What is not included in the scope for this chapter is the specifics of embedded implementation and low-latency signal-processing pipeline design, training and deploying the on-device ML height-classification model, and the structure of the Unreal Engine output interface are addressed by other technical sub-questions in the project plan's research questions.
This chapter recommends which sensor(s) to use and how to validate that choice, not how the resulting embedded software is built.
Per xref:../../project-plan/project-assignment/scope-preconditions.adoc[Scope and Preconditions], a fully polished prototype ready for a non-controlled environment is explicitly out of scope for this project, since it is exploratory by nature; the recommendation in this chapter reflects that by ending in a staged prototyping plan rather than a final hardware order.

Two aspects of the research question are also narrowed for this stage.
Distinguishing adult and child height *categories*, as literally asked above, is treated as a possible later refinement rather than a hard requirement now: a general height estimate is sufficient for this stage (see Candidate Sensor Technologies).
Multi-person tracking is explicitly a future-facing requirement in the project assignment, not part of this project's build scope; it is addressed here only as one of the criteria technologies are evaluated against (see Evaluation Criteria), not as a capability this stage implements.
If time does allow it, these aspects will be looked further into and possibly integrated (to some extent).
