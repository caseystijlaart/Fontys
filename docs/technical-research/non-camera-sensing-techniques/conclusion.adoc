= Conclusion

Candidate Sensor Technologies weighed the technically viable sensors and sensor combinations against the criteria in Evaluation Criteria.
On that basis, mmWave radar is recommended directly: it is the only approach with keypoint-level pose literature for height estimation, it extends to the RQ4 active-speaker problem via the same sensor, its output is inherently non-identifying, and it has the strongest literature base of any candidate reviewed.
Within the TI IWR6843 family, Module Selection picks the *IWR6843AOPEVM*: its antenna-on-package design gives the wide 120° elevation field of view needed for room-scale height coverage without a separate antenna to design around, in a compact, mount-agnostic form factor at roughly the same price as the cheaper plain LEVM variant.

Rather than deferring mmWave behind a cheaper sensor, implementation risk is managed by splitting the mmWave build itself into capability-based phases: position tracking first, then height estimation, then multi-person clustering, then speaker detection, each building on an already-working previous phase.
This still isolates risk (a problem in one capability does not require redoing the whole pipeline) without introducing a second sensor and a mid-project hardware swap.
mmWave remains, by a wide margin, the most expensive candidate reviewed, and no project budget has yet been agreed with MindLabs, so mentor approval of the full mmWave hardware cost is a precondition for this plan, not a detail to resolve later.

Sensor fusion, combining mmWave (or 2D LiDAR) with a second thermal sensor, was deliberately not adopted as the starting recommendation, even though the project's own risk analysis anticipated it as a likely need.
mmWave alone already has a plausible, literature-backed path to a height estimate via keypoint/pose extraction, so a second sensor is not needed to attempt a first working pipeline; fusion is kept as a documented fallback for if that estimate underperforms once measured, not a precondition for starting.
Committing to fusion upfront would also mean paying its cost and complexity before that need is established: none of the three fusion combinations evaluated has been tested together in the literature (each half is validated separately, not the pair), the thermal side requires two units (split to jointly cover the room, rather than one) to match mmWave's room-scale coverage, adding real cost rather than a marginal add-on, and for 2D LiDAR + Thermal specifically, fusing two independent position-sensing streams from scratch was flagged as a disproportionate implementation risk for this project's timeline.
Starting with mmWave alone keeps a working single-sensor system as the baseline throughout the phased build, and only asks for the added cost and complexity of a second sensor if the single-sensor result actually falls short.
