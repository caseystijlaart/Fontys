= Requirements

A system has various requirements, each one covering an important aspect of how the system must work or behave.
These requirements are divided into the user-, functional- and non-functional requirements.
They reflect the system as realized in firmware v1.1.0.

== User Requirements

.User Requirements
[cols="2,15,3"]
|===
| ID | Requirement | Use Case(s)

| UR_001 | The user should be able to add a new plant by pairing a device and entering its care requirements. | UC01
| UR_002 | The user should be able to monitor the health status of a plant. | UC02, UC03
| UR_003 | The user should be able to view current and historical plant data. | UC03
| UR_004 | The user should be able to update plant care settings. | UC04
| UR_005 | The user should receive notifications and care recommendations when abnormal conditions occur. | UC05
| UR_006 | The user should be able to request an immediate measurement on demand. | UC06
| UR_007 | The user should be able to remove a device so it can be re-paired. | UC07
|===

== Functional Requirements

.Functional Requirements
[cols="2,15,3"]
|===
| ID | Requirement | Use Case(s)

| FR_001 | The user interface must allow the user to input plant details and preferences when adding a plant. | UC01
| FR_002 | The data storage must store device registrations, plant profiles, and associated care settings. | UC01, UC04
| FR_003 | The edge node must support BLE provisioning to receive WiFi credentials and cloud configuration from the user interface. | UC01
| FR_004 | The edge node must register itself in the data storage after provisioning and persist its pairing state locally. | UC01
| FR_005 | The sensor array must provide environmental data: soil moisture, temperature, humidity, and light level. | UC02
| FR_006 | The edge node must read sensor data and derive a feature vector from the recent measurement history. | UC02
| FR_007 | The edge node must use an on-device ML model to classify plant health and predict the time until watering is needed. | UC02, UC05
| FR_008 | The edge node must store measurement results locally and send sensor data, predictions, and model metrics to the data storage. | UC02
| FR_009 | The data storage must provide plant data when requested by the user interface. | UC03
| FR_010 | The user interface must display current and historical plant data. | UC03
| FR_011 | The user interface must allow the user to update plant care settings, and the edge node must fetch the updated profile before each scheduled cycle. | UC04
| FR_012 | The edge node must detect abnormal conditions and generate care recommendations based on sensor data and predictions. | UC05
| FR_013 | The user interface must notify the user when abnormal conditions are detected. | UC05
| FR_014 | The edge node must poll the data storage for command flags and run an immediate monitoring cycle when a measurement is requested. | UC06
| FR_015 | The edge node must perform a full factory reset (clear history, pairing state, cloud registration, and device storage) when removal is requested. | UC07
|===

== Non-Functional Requirements

.Non-Functional Requirements
[cols="2,18"]
|===
| ID | Requirement

| NFR_001 | The system should be modular so components can be updated or replaced independently.
| NFR_002 | The system should support multiple edge nodes and plants.
| NFR_003 | The edge node must operate within embedded hardware constraints such as limited memory and processing power (ML inference, BLE, and TLS combined on a single ESP32).
| NFR_004 | WiFi credentials and the cloud API key must not be stored in the firmware binary; they are transferred once over BLE during provisioning, and removing a device must erase them.
| NFR_005 | The edge node should operate autonomously after provisioning, without requiring the user interface to be active.
|===
