= Data Structure

There are many types of data structures that can be used for a database.
Each type is used for a different purpose.
Examples of such are tables, indexes, trees and heaps.
When picking a data structure it is of great importance to keep in mind in what type of database it is stored.

As discussed in <<Recommendations Database Structure>>, the recommendation is to make use of an local non-relational database, NoSQL. 
This local database will be stored on a physical drive. 
Based upon this, it is a given that there is made use of flexible tables.
Tables, though seemingly straightforward, offer a spectrum of techniques to enhance their utility.

Techniques of such are Key-Value Stores and indexes.
These two techniques can enhance performance and overall clarity of the database.

== Data Structure Techniques

== Key-Value Stores

Key-value stores are a simple yet powerful data structure. They store data as pairs of keys and corresponding values. Key-value stores are highly efficient for data retrieval based on a unique identifier (the key).

**Purpose**

Key-value stores are particularly advantageous when rapid access to individual data components is essential, allowing for efficient data retrieval based on unique identifiers (the keys).

=== Indexes

An index in a non-relational database is a data structure that improves the speed of data retrieval operations on a table.
It's like an additional table containing a subset of the data in the main table, organized for quick lookup based on one or more columns.

**Purpose**

Indexes are used to speed up the retrieval of rows from a table. 
Without an index, the database would need to perform a full table scan to find specific rows, which can be slow for large datasets. 
Indexes allow the database engine to locate the desired rows more efficiently.

**Types of Indexes**
There are various types of indexes, including B-tree indexes (commonly used for most data types), hash indexes (for exact matches), and bitmap indexes (useful for columns with a limited set of possible values).


== Recommendation

For the prototype, the recommendation is to make use of tables with the Key-Value Stores technique to efficiently store and retrieve data. 
If feasible, incorporating indexes, especially on relevant attributes such as "SensorID," is highly recommended. 
Indexes facilitate faster data processing, ensuring that data can be received and retrieved in a continuous, uninterrupted stream.
