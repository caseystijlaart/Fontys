== Holobox mmWave Implementation Guide: Block-by-Block

This guide provides practical, step-by-step implementation details for each modular block of the mmWave sensing system. Each block is designed to be developed and validated independently, with clear input/output contracts and measurable success criteria.

=== Prerequisites

**Hardware:**
- TI IWR6843 mmWave radar module or evaluation kit (~€80–250)
- Raspberry Pi 4 (4GB+ RAM recommended) or x86-64 Linux development machine
- USB-to-UART adapter (if module doesn't include one)

**Software Stack:**
- C++17 or later (GCC 9+, or Clang)
- CMake 3.15+
- Eigen 3.x (header-only linear algebra)
- OpenCV 4.x (clustering, filtering utilities)
- TensorFlow Lite (for Block 1b inference)
- Boost (optional: for circular buffers in filtering)

**Development Workflow:**
- All blocks developed in C++; Python scripts only for offline data analysis and ML training
- Real-time constraints: 10 Hz output minimum (100 ms per frame)
- Modular design: each block compiles independently; integration via simple function signatures

== Block 1: Position Localization (x, y)

**Goal:** Raw mmWave point cloud → cluster centroid → room-absolute (x, y, z) position tuple at 10 Hz.

**Timeline:** 2 weeks

**Validation Success Criterion:** Person walks known path (e.g., diagonal line, circle) in room; estimated (x, y, z) matches ground truth position within ±0.5 m.

=== Step 1.1: UART Driver and Point Cloud Parsing

**Objective:** Read raw point cloud from TI IWR6843 via UART serial protocol; parse into usable format.

**Implementation Approach:**

[source,cpp]
----

        float doppler;           // velocity, m/s
        float intensity;         // radar reflectivity

    void sendConfig(const std::string& config_file);

private:

    const size_t MAX_POINTS = 1024;  // IWR6843 typical max

----

**Key Implementation Details:**

1. **Serial Configuration:** IWR6843 outputs at 115200 baud, ~30 Hz frame rate (33 ms per frame)
   - Frame format: header (4 bytes) + TLV structures + checksum (2 bytes)
   - Each TLV (type-length-value) contains detected points, range/Doppler info, or noise statistics

2. **Reference Implementation Source:** Use TI's `mmwave_sdk_03_06_00_13/examples/out_of_box/xwr6843_miniiot_demo/` as guide
   - File: `src/common/mmwave_frame_parser.c` (C reference; translate to C++)
   - Key: Don't reimplement CRC; use TI's polynomial (0x8005)

3. **Point Cloud Output Format:**
   ```
   TLVTYPE_DETECTED_POINTS (0x0001):
   - num_detected_points (4 bytes)
   - For each point: x(4B), y(4B), z(4B), doppler(2B), intensity(2B)
   ```

4. **Testing Strategy:**
   - Use TI's **visualizer** (real-time point cloud display) to verify UART output is valid
   - Capture raw frames to file; parse offline first before streaming real-time
   - Validate CRC on every frame; log dropped frames

5. **Error Handling:**
   - Serial port timeouts: if no frame received in 100 ms, log "frame loss" and continue
   - CRC failures: skip frame, wait for next sync marker
   - Don't crash on malformed data; degrade gracefully

**Estimated Effort:** 1 week (UART + parsing ~3 days, integration testing ~2 days, documentation ~2 days)

=== Step 1.2: DBSCAN Clustering

**Objective:** Group point cloud into person-sized clusters; extract cluster centroids.

**Implementation Approach:**

[source,cpp]
----
#include <Eigen/Dense>
#include <vector>
#include <algorithm>

struct Cluster {
    std::vector<size_t> point_indices;  // indices into original point cloud
    Eigen::Vector3f centroid;           // (x, y, z) center
    float radius;                       // point cloud spread
    size_t num_points;
    float mean_intensity;
    float doppler_variance;

    // Geometry features for clutter classification (Block 1b)
    Eigen::Vector3f bbox_min, bbox_max;
    float height() const { return bbox_max(2) - bbox_min(2); }
    float area_xy() const {
        return (bbox_max(0) - bbox_min(0)) * (bbox_max(1) - bbox_min(1));
    }
    float density() const {
        float volume = (bbox_max(0) - bbox_min(0)) *
                       (bbox_max(1) - bbox_min(1)) *
                       (bbox_max(2) - bbox_min(2));
        return (volume > 0) ? static_cast<float>(num_points) / volume : 0.0f;
    }
};

class DBSCANClustering {
public:
    // DBSCAN parameters: room-dependent calibration
    struct Params {
        float epsilon = 0.35f;      // neighborhood radius, meters (TUNE THIS)
        size_t min_points = 5;      // minimum cluster size (TUNE THIS)
    };

    std::vector<Cluster> cluster(
        const PointCloudFrame& frame,
        const Params& params = Params()
    );

private:
    enum PointLabel { UNVISITED = -1, NOISE = -2 };

    std::vector<int> labels_;

    std::vector<size_t> regionQuery(
        const std::vector<Eigen::Vector3f>& points,
        size_t point_idx,
        float epsilon
    );

    void expandCluster(
        const std::vector<Eigen::Vector3f>& points,
        std::vector<int>& labels,
        size_t point_idx,
        std::vector<size_t>& neighbors,
        int cluster_id,
        float epsilon,
        size_t min_points
    );
};

std::vector<Cluster> DBSCANClustering::cluster(
    const PointCloudFrame& frame,
    const Params& params
) {
    // Convert point cloud to Eigen vectors for fast distance computation
    std::vector<Eigen::Vector3f> points;
    for (const auto& p : frame.points) {
        points.push_back(Eigen::Vector3f(p.x, p.y, p.z));
    }

    // Initialize labels
    labels_.assign(points.size(), UNVISITED);
    int cluster_id = 0;

    // DBSCAN main loop
    for (size_t i = 0; i < points.size(); ++i) {
        if (labels_[i] != UNVISITED) continue;

        auto neighbors = regionQuery(points, i, params.epsilon);

        if (neighbors.size() < params.min_points) {
            labels_[i] = NOISE;
        } else {
            expandCluster(points, labels_, i, neighbors, cluster_id,
                         params.epsilon, params.min_points);
            ++cluster_id;
        }
    }

    // Build cluster objects from labels
    std::vector<Cluster> clusters;
    for (int cid = 0; cid < cluster_id; ++cid) {
        Cluster c;
        for (size_t i = 0; i < labels_.size(); ++i) {
            if (labels_[i] == cid) {
                c.point_indices.push_back(i);
                c.centroid += points[i];
                c.mean_intensity += frame.points[i].intensity;
                c.doppler_variance += frame.points[i].doppler * frame.points[i].doppler;
            }
        }

        c.num_points = c.point_indices.size();
        c.centroid /= static_cast<float>(c.num_points);
        c.mean_intensity /= static_cast<float>(c.num_points);
        c.doppler_variance /= static_cast<float>(c.num_points);

        // Compute bounding box
        c.bbox_min = c.bbox_max = points[c.point_indices[0]];
        for (size_t idx : c.point_indices) {
            c.bbox_min = c.bbox_min.cwiseMin(points[idx]);
            c.bbox_max = c.bbox_max.cwiseMax(points[idx]);
        }

        clusters.push_back(c);
    }

    return clusters;
}
----

**Tuning DBSCAN Parameters:**

The two critical hyperparameters must be calibrated to your room geometry and sensor mounting:

1. **Epsilon (neighborhood radius):**
   - Start: 0.35 m (assumes ~10 cm detection error + clustering margin)
   - If clusters merge with neighbors → increase epsilon by 0.05 m
   - If single person splits into multiple clusters → decrease epsilon by 0.05 m
   - Typical range: 0.3–0.5 m for indoor spaces
   - **Calibration procedure:**
     ```
     1. Place two people 0.8 m apart (back-to-back in room center)
     2. Record raw point cloud
     3. Run DBSCAN with epsilon = 0.3, 0.35, 0.4, 0.45
     4. Plot clusters; pick epsilon where two people form separate clusters
     ```

2. **Min Points (minimum cluster size):**
   - Start: 5 points (conservative; most people → 20–50 points at 2–3 m distance)
   - If false clusters (furniture reflections) detected → increase to 8–10
   - If real person clusters rejected as noise → decrease to 3–4
   - Typical range: 5–15 points

**Important Notes:**

- DBSCAN does NOT assign persistent IDs across frames (no multi-target tracking). Clusters are identified by position only; re-identification across frames is handled by Kalman filtering (Step 1.3).
- Use KD-tree for fast neighbor search (Eigen doesn't provide this; use Boost or nanoflann header-only library).
- Computational cost: O(n log n) with tree acceleration; <10 ms per frame typical on Raspberry Pi 4.

**Validation:**
- Record 100 frames of point clouds from a stationary person
- Run DBSCAN; visualize cluster centroids overlaid on raw cloud
- Check: centroid should stay within 0.3 m of person's actual position

=== Step 1.3: Room Calibration and Coordinate Transformation

**Objective:** Transform sensor-relative point cloud coordinates to room-absolute coordinates.

**Implementation Approach:**

The mmWave sensor outputs (x, y, z) in its own reference frame (origin at sensor). To track position in the room, we need a linear transformation:

$$\text{room\_coord} = R \cdot \text{sensor\_coord} + T$$

where $R$ is a 3×3 rotation matrix and $T$ is a 3×1 translation vector.

**Simple Case (Front-Mounted, Level Sensor):**

If the sensor is mounted front-facing at height $h$ above the floor, oriented parallel to room axes:

=== Step 1.4: Kalman Filtering for Position Smoothing

**Objective:** Smooth noisy cluster centroid estimates and estimate velocity; handle temporary occlusions.

**Implementation Approach:**

A standard 3D Kalman filter predicts position and velocity. Key insight: between frames, we predict where the person is moving; when we receive a new cluster, we update.

[source,cpp]
----
#include <Eigen/Dense>

class KalmanFilter3D {
public:
    struct State {
        Eigen::Vector3f position;      // (x, y, z)
        Eigen::Vector3f velocity;      // (vx, vy, vz) m/s
    };

    KalmanFilter3D(float dt = 0.1f);  // 10 Hz frame rate

    void predict();
    void update(const Eigen::Vector3f& measurement);
    State getState() const { return {x_.head<3>(), x_.tail<3>()}; }
    float getUncertainty() const;

private:
    float dt_;
    Eigen::VectorXf x_;                    // state: [px, py, pz, vx, vy, vz]
    Eigen::MatrixXf P_;                    // covariance
    Eigen::MatrixXf F_;                    // state transition (constant velocity model)
    Eigen::MatrixXf Q_;                    // process noise
    Eigen::MatrixXf H_;                    // measurement matrix (position only observed)
    Eigen::MatrixXf R_;                    // measurement noise
};

KalmanFilter3D::KalmanFilter3D(float dt) : dt_(dt) {
    x_ = Eigen::VectorXf::Zero(6);
    P_ = Eigen::MatrixXf::Identity(6, 6) * 0.1f;  // initial uncertainty

    // Constant-velocity model: x_new = x_old + v * dt
    F_ = Eigen::MatrixXf::Identity(6, 6);
    F_.block<3, 3>(0, 3) = dt * Eigen::Matrix3f::Identity();

    // Process noise (model uncertainty)
    Q_ = Eigen::MatrixXf::Identity(6, 6) * 0.01f;
    Q_.block<3, 3>(3, 3) *= 0.01f;  // lower noise on acceleration

    // Measure only position, not velocity
    H_ = Eigen::MatrixXf::Zero(3, 6);
    H_.block<3, 3>(0, 0) = Eigen::Matrix3f::Identity();

    // Measurement noise (sensor accuracy ~0.3 m)
    R_ = Eigen::Matrix3f::Identity() * 0.09f;
}

void KalmanFilter3D::predict() {
    x_ = F_ * x_;
    P_ = F_ * P_ * F_.transpose() + Q_;
}

void KalmanFilter3D::update(const Eigen::Vector3f& measurement) {
    Eigen::Vector3f y = measurement - H_ * x_;  // innovation
    Eigen::MatrixXf S = H_ * P_ * H_.transpose() + R_;
    Eigen::MatrixXf K = P_ * H_.transpose() * S.inverse();

    x_ += K * y;
    P_ = (Eigen::MatrixXf::Identity(6, 6) - K * H_) * P_;
}
----

**Tuning Guidance:**

1. **Process Noise (Q):** Higher Q → filter trusts predictions less, follows measurements closely
   - Start with Q_pos = 0.01 m², Q_vel = 0.0001 m²/s²
   - If smoothed trajectory lags behind measurement → increase Q_pos
   - If smoothed trajectory jitters → decrease Q_pos

2. **Measurement Noise (R):** Set based on sensor accuracy
   - IWR6843 achieves ~±0.3 m positioning error → R = 0.09 m²
   - Can be estimated empirically: record stationary person, compute variance of cluster centroids

3. **Handling Occlusions:** If no cluster detected in frame:
   - Call `predict()` only (no `update()`)
   - Kalman filter continues predicting motion; re-establishes with measurement when person reappears
   - Safe timeout: 0.5–1 s (5–10 frames at 10 Hz)

**Validation:**
- Record 5 minutes of position data (walk around room, stop, move again)
- Plot raw cluster centroids vs. Kalman-filtered positions
- Check: Kalman trajectory smooth, no lag >100 ms, recovers after brief occlusions

== Block 1b: Clutter Classification (ML-based Filtering)

**Goal:** Filter DBSCAN clusters, removing false positives from wall reflections, furniture corners, sensor noise.

**Timeline:** 1.5 weeks (1 week data collection + training, 0.5 weeks integration)

**Validation Success Criterion:** Reduce false positive cluster rate from ~20–30% (raw DBSCAN) to <5% while maintaining >99% detection of real people.

=== Step 1b.1: Data Collection and Labeling

**Objective:** Collect 100–150 labeled (point cloud, ground truth cluster label) samples.

**Data Collection Procedure:**

1. **Setup:**
   - Run Block 1 in "recording mode": save point cloud frames + raw centroids to disk
   - Record for 10–15 minutes while performing these movements:
     - Walk slowly around room perimeter (3 laps)
     - Walk diagonals (4 passes)
     - Stand still in corner and center (2 min each)
     - Walk near walls, furniture (2 min)
     - User walks away; room empty (1 min) to capture pure noise/clutter

2. **Labeling:**
   - Write a visualization script: render point cloud + clusters from saved frames
   - For each frame, manually label each cluster: "PERSON" (1) or "CLUTTER" (0)
   - False positive examples:
     - Cluster from wall reflection (typically small, low doppler)
     - Cluster from furniture corner (high density, odd geometry)
     - Acoustic reflections (scattered points, no coherent centroid)

3. **Feature Extraction:**

[source,cpp]
----
struct ClusterFeatures {
    size_t num_points;                    // raw count
    float height;                         // bbox_max.z - bbox_min.z (meters)
    float width;                          // bbox_max.x - bbox_min.x
    float depth;                          // bbox_max.y - bbox_min.y
    float density;                        // points / volume
    float mean_intensity;                 // radar reflectivity (0–255)
    float mean_doppler;                   // velocity magnitude (m/s)
    float centroid_height;                // z coordinate (meters above floor)
    float surface_area;                   // estimated from bounding box

    // Derived features
    float aspect_ratio_hw() const { return (width > 0) ? height / width : 1.0f; }
    float aspect_ratio_hd() const { return (depth > 0) ? height / depth : 1.0f; }
    float normalized_density() const { return std::min(density, 100.0f) / 100.0f; }
};

ClusterFeatures extractFeatures(const Cluster& cluster, const PointCloudFrame& frame) {
    ClusterFeatures f;
    f.num_points = cluster.num_points;
    f.height = cluster.height();
    f.width = cluster.bbox_max(0) - cluster.bbox_min(0);
    f.depth = cluster.bbox_max(1) - cluster.bbox_min(1);
    f.density = cluster.density();

    f.mean_intensity = cluster.mean_intensity;
    f.mean_doppler = 0;
    f.centroid_height = cluster.centroid(2);
    f.surface_area = 2 * (f.width * f.height + f.height * f.depth + f.width * f.depth);

    // Compute mean doppler from cluster points
    float doppler_sum = 0;
    for (size_t idx : cluster.point_indices) {
        doppler_sum += std::abs(frame.points[idx].doppler);
    }
    f.mean_doppler = doppler_sum / static_cast<float>(f.num_points);

    return f;
}

=== Step 1b.3: C++ Inference and Integration

**Objective:** Load TensorFlow Lite model; classify clusters in real-time.

[source,cpp]
----
#include "tensorflow/lite/interpreter.h"
#include "tensorflow/lite/kernels/register.h"
#include "tensorflow/lite/model.h"

class ClutterClassifier {
public:
    ClutterClassifier(const std::string& model_path);

    // Returns probability (0–1) that cluster is a PERSON
    float classify(const ClusterFeatures& features);

private:
    std::unique_ptr<tflite::FlatBufferModel> model_;
    std::unique_ptr<tflite::Interpreter> interpreter_;

    // Normalization parameters (fit during training, hardcode here)
    const std::vector<float> feature_means_ = {
        30, 1.6, 0.5, 0.5, 3.0, 100, 0.15, 1.2, 2.0, 1.0
    };
    const std::vector<float> feature_stds_ = {
        15, 0.3, 0.3, 0.3, 1.5, 50, 0.1, 0.4, 1.0, 0.5
    };
};

ClutterClassifier::ClutterClassifier(const std::string& model_path) {
    model_ = tflite::FlatBufferModel::BuildFromFile(model_path.c_str());

    tflite::ops::builtin::BuiltinOpResolver resolver;
    tflite::InterpreterBuilder builder(*model_, resolver);
    builder(&interpreter_);

    interpreter_->AllocateTensors();
}

float ClutterClassifier::classify(const ClusterFeatures& features) {
    // Extract and normalize features
    std::vector<float> raw_features = {
        static_cast<float>(features.num_points),
        features.height,
        features.width,
        features.depth,
        features.density,
        features.mean_intensity,
        features.mean_doppler,
        features.centroid_height,
        features.surface_area,
        features.aspect_ratio_hw()
    };

    std::vector<float> normalized_features(raw_features.size());
    for (size_t i = 0; i < raw_features.size(); ++i) {
        normalized_features[i] = (raw_features[i] - feature_means_[i]) / (feature_stds_[i] + 1e-8f);
    }

    // Fill input tensor
    float* input = interpreter_->typed_input_tensor<float>(0);
    std::copy(normalized_features.begin(), normalized_features.end(), input);

    // Invoke
    interpreter_->Invoke();

    // Read output
    float* output = interpreter_->typed_output_tensor<float>(0);
    return output[0];  // Probability in [0, 1]
}

**Tuning the Confidence Threshold:**

- **0.9 (very conservative):** Almost no false positives, but may miss people at distance/occlusion
- **0.7 (balanced, recommended):** ~95% precision, ~99% recall
- **0.5 (permissive):** Catches edge cases but includes some clutter

Validate on held-out test set; choose threshold where false positive rate < 5%.

== Block 2: Height Estimation (Heuristic)

**Goal:** Estimate rough height classification (child ~1.0–1.3 m, adult ~1.6–1.8 m) for virtual human response.

**Timeline:** 1 day

**Validation Success Criterion:** Binary classification (child vs. adult) correct >90% of the time.

=== Step 2.1: Height Heuristic Implementation

**Objective:** Extract height from point cloud vertical extent; apply threshold for child/adult decision.

[source,cpp]
----
class HeightEstimator {
public:
    enum HeightClass { CHILD, ADULT, UNKNOWN };

    HeightClass estimateHeight(const Cluster& cluster) const;

private:
    // Thresholds (calibrate for your sensor + mounting)
    const float CHILD_ADULT_THRESHOLD = 1.4f;  // meters
};

HeightEstimator::HeightClass HeightEstimator::estimateHeight(const Cluster& cluster) const {
    // Option A: Use vertical extent of cluster
    float estimated_height = cluster.bbox_max(2) - cluster.bbox_min(2);

    // Option B: Use nominal height (simple fallback)
    // float estimated_height = 1.6f;  // assume adult

    if (estimated_height < CHILD_ADULT_THRESHOLD) {
        return CHILD;
    } else if (estimated_height > 0.8f) {  // minimum height threshold to avoid noise
        return ADULT;
    } else {
        return UNKNOWN;
    }
}

// Usage in main pipeline
HeightEstimator height_estimator;
for (const auto& cluster : filtered_clusters) {
    auto height_class = height_estimator.estimateHeight(cluster);

    // Send to Unreal Engine
    if (height_class == HeightEstimator::CHILD) {
        virtual_human.setPosture(VirtualHuman::KNEELING);
    } else if (height_class == HeightEstimator::ADULT) {
        virtual_human.setPosture(VirtualHuman::STANDING);
    }
}
----

**Why Heuristic Over ML:**

- **Heuristic accuracy:** 70–80% correct child/adult classification
- **ML accuracy gain:** +5–10% (80–85% at best)
- **ML development cost:** 2 additional weeks (data collection, labeling, training)
- **Timeline trade-off:** Not justified for 16-week project where core localization and multi-person tracking are priorities

**Calibration:**

1. Record 30 frames each: child standing in room, adult standing in same location
2. Extract bbox_max(2) - bbox_min(2) for each
3. Find threshold that best separates distributions
4. Typical threshold: 1.3–1.5 m (depends on sensor mounting height and angle)

== Integration with Unreal Engine

**Goal:** Stream (x, y, z) position + height class from mmWave system to Unreal Engine at 10 Hz.

=== Communication Protocol

Use **TCP socket** for reliable, low-latency streaming:

[source,cpp]
----
#include <boost/asio.hpp>
#include <nlohmann/json.hpp>

using json = nlohmann::json;

class UnrealEngineSocket {
public:
    UnrealEngineSocket(const std::string& server_ip = "127.0.0.1",
                       uint16_t port = 9999);
    bool connect();
    void sendTracking(const std::vector<Cluster>& clusters,
                      const std::vector<HeightEstimator::HeightClass>& heights);

private:
    boost::asio::io_context io_;
    std::unique_ptr<boost::asio::ip::tcp::socket> socket_;
};

void UnrealEngineSocket::sendTracking(
    const std::vector<Cluster>& clusters,
    const std::vector<HeightEstimator::HeightClass>& heights
) {
    json msg = json::object();
    msg["timestamp"] = std::time(nullptr);
    msg["num_people"] = clusters.size();

    json people = json::array();
    for (size_t i = 0; i < clusters.size(); ++i) {
        json person = {
            {"id", i},
            {"x", clusters[i].centroid(0)},
            {"y", clusters[i].centroid(1)},
            {"z", clusters[i].centroid(2)},
            {"vx", 0},  // (velocity would come from Kalman filter)
            {"vy", 0},
            {"height_class", heights[i] == HeightEstimator::CHILD ? "CHILD" : "ADULT"}
        };
        people.push_back(person);
    }
    msg["people"] = people;

    std::string payload = msg.dump() + "\n";
    boost::asio::write(*socket_, boost::asio::buffer(payload));
}
----

**JSON Message Format:**

```json
{
  "timestamp": 1693833600,
  "num_people": 2,
  "people": [
    {
      "id": 0,
      "x": 1.5,
      "y": 2.1,
      "z": 1.6,
      "vx": 0.05,
      "vy": -0.02,
      "height_class": "ADULT"
    },
    {
      "id": 1,
      "x": 0.8,
      "y": 1.2,
      "z": 1.1,
      "vx": 0.0,
      "vy": 0.0,
      "height_class": "CHILD"
    }
  ]
}
```

**Unreal Engine Receiver (Blueprint pseudocode):**

```
Event BeginPlay:
    Connect to socket (127.0.0.1:9999)
    Start receive thread

On socket message received:
    Parse JSON
    For each person in message:
        - Update virtual human position (x, y)
        - Update virtual human height class (kneel/stand)
        - Update head look-at target based on height

Tick (at 30 Hz Unreal):
    Interpolate position between incoming messages (10 Hz)
    Apply smooth animation blending
```

== Troubleshooting Guide

| Problem | Cause | Solution |
|---------|-------|----------|
| No point cloud received | Serial port not opening | Check USB permissions, baud rate, port name |
| Clusters split across multiple blobs | DBSCAN epsilon too small | Increase epsilon by 0.05–0.1 m, re-calibrate |
| Clusters merge with wall reflections | epsilon too large, OR low min_points | Increase min_points to 8–10; use Block 1b ML to filter |
| Room calibration drift | Sensor mounting shifted | Re-calibrate transformation matrix; store to file with timestamp |
| Kalman filter lags behind movement | Process noise Q too low | Increase Q_pos from 0.01 to 0.05–0.1 |
| Height estimation wrong | Threshold not calibrated | Run calibration procedure: record child and adult, measure bbox vertical extent |
| Inference latency >1 ms | CPU bottleneck on Raspberry Pi | Profile with `time` command; consider running on higher-performance machine |
